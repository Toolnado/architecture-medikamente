# Задание 3. Data Encryption at Rest and In Transit

## Классификация и инструменты защиты

| Данные | Состояние | Класс / профиль риска | В чём необходимость защиты | At Rest | In Transit | Автоматизированный контроль |
|---|---|---|---|---|---|---|
| Ф. И. О., дата рождения, адрес, телефон, email | БД, файлы, API | `STRICT`, высокий риск идентификации | Утечка позволяет идентифицировать пациента и связать его с обращением | Шифрование диска и БД, шифрование полей, KMS, зашифрованные бэкапы | TLS 1.3, mTLS между сервисами | DLP, ABAC, аудит чтения и выгрузки |
| Диагнозы, жалобы, хронические заболевания, заключения | БД, сканы, API | `STRICT`, критический медицинский риск | Врачебная тайна; раскрытие может причинить прямой вред | Отдельный ключ домена «Медицина», шифрование объектов и резервных копий | mTLS, сервисные токены с коротким сроком жизни | SIEM, запрет массовой выгрузки, контроль аномального доступа |
| Направления и результаты анализов | БД, документы, интеграция с лабораторией | `STRICT`, критический риск целостности | Ошибочный или подменённый результат влияет на лечение | Шифрование БД и объектного хранилища, контроль целостности | mTLS, подписанные сообщения, защита от повторной отправки | Сверка идентификаторов и статусов, карантин ошибок |
| Договоры, согласия и сканы | Объектное хранилище, архив | `STRICT`, высокий юридический риск | Содержат полный набор ПДн и подтверждают основание обработки | SSE-KMS/шифрование объектов, WORM для нужных документов | TLS, одноразовые ссылки на скачивание | Версионирование, аудит, сроки хранения и legal hold |
| Записи на приём | БД, API, события | `CONFIDENTIAL`, средний/высокий риск | Раскрывают факт обращения и график специалиста | Шифрование БД и бэкапов | TLS/mTLS, подпись событий | RBAC/ABAC, идемпотентность, аудит изменений |
| Платежи и чеки | БД, ККМ, 1С | `CONFIDENTIAL`, высокий финансовый риск | Требуются целостность, сверяемость и защита реквизитов | Шифрование БД, дисков 1С и бэкапов; токенизация платёжных реквизитов | TLS/mTLS, VPN для административных интеграций | Автоматическая сверка, antifraud-правила, журнал операций |
| Кадры и зарплата сотрудников | Файловая 1С, архив | `STRICT`, высокий риск для сотрудников | Персональные и финансовые данные доступны только HR/бухгалтерии | Шифрование дисков и бэкапов, отдельные ключи и ACL | TLS/VPN при удалённом доступе | Разделение ролей, аудит и DLP |
| Технические логи и идентификаторы | SIEM, логи приложений | `CONFIDENTIAL`, средний риск | Логи могут раскрыть ПДн, токены и структуру системы | Шифрование журналов, неизменяемое хранилище | TLS/mTLS до коллектора | Фильтрация секретов и ПДн, контроль целостности и retention |
| Учётные данные и ключи | Vault/KMS/HSM | `STRICT`, критический системный риск | Компрометация открывает доступ ко всем данным | KMS/Vault, HSM для мастер-ключей, ротация и разделение обязанностей | Только защищённые служебные каналы, без передачи секретов в логах | Контроль срока жизни, отзыв, аудит использования ключей |

## Реестр средств защиты

| Назначение | Программные средства | Аппаратные / инфраструктурные средства |
|---|---|---|
| Управление ключами | KMS или Vault, автоматическая ротация, envelope encryption | HSM для мастер-ключей |
| Базы данных | PostgreSQL `pgcrypto` для выбранных полей, шифрование томов, TLS | Зашифрованные диски и изолированные узлы БД |
| Файлы и резервные копии | SSE-KMS, шифрование архивов, проверка восстановления | Отдельное резервное хранилище по правилу 3-2-1 |
| Защита каналов | TLS 1.3 на ingress, mTLS между сервисами, VPN для администрирования | Межсетевой экран и сегментация сети |
| Доступ | IAM, OIDC/OAuth 2.0, RBAC/ABAC, MFA для сотрудников | Аппаратный второй фактор для привилегированных ролей |
| Контроль | DLP, SIEM, аудит БД и API, сканирование конфигураций | Неизменяемое хранилище журналов |

Ключи не хранятся рядом с данными. Для доменов «Медицина», «Лаборатория», «Договоры» и «Платежи» используются разные ключи, чтобы компрометация одного домена не раскрывала остальные.

## Профиль ИСПДн и выбор средств

Внутренний класс `STRICT` не заменяет юридическую классификацию. Медицинские сведения относятся к специальным категориям ПДн, а кадровые, контактные и платёжные сведения классифицируются отдельно. До выбора окончательной конфигурации средств защиты компания должна определить актуальные угрозы и уровень защищённости по ПП РФ № 1119, после чего выбрать меры из приказа ФСТЭК № 21. Если модель угроз или условия интеграции требуют применения сертифицированной криптографии, конкретные СКЗИ и HSM выбираются совместно со специалистом по ИБ с учётом действующих сертификатов.

| Средство / реализация | Объект защиты | Владелец | Автоматизированный контроль | Статус для целевой архитектуры |
|---|---|---|---|---|
| HashiCorp Vault или совместимый корпоративный KMS | Data keys, секреты сервисов, ротация | Специалист по ИБ | Возраст ключа, ошибки ротации, аудит операций | Добавить в платформенный контур |
| HSM с требуемой сертификацией | Мастер-ключи и операции повышенного риска | Специалист по ИБ | Доступность, попытки несанкционированных операций | Выбрать после модели угроз |
| PostgreSQL TLS + шифрование тома; `pgcrypto` только для выбранных полей | Операционные БД | DBA/DevOps | Проверка TLS, конфигурации, резервного копирования и восстановления | Включить по умолчанию |
| S3-совместимое объектное хранилище с SSE-KMS, versioning и Object Lock | PDF/JPG, договоры, результаты и архив | Data Platform owner | Нешифрованные объекты, истечение retention, изменение политики | Добавить вместо общего диска |
| OIDC IAM + MFA + policy engine | Доступ людей и сервисов | IAM owner | Неуспешные входы, выдача привилегий, access review | Обязательный общий сервис |
| API Gateway и service mesh с TLS 1.3/mTLS | Внешние и внутренние каналы | Platform team | Срок сертификатов, plaintext endpoints, ошибки авторизации | Обязательный ingress/east-west слой |
| SIEM + неизменяемое хранилище аудита | События доступа, изменения, выгрузки и удаления | SOC/специалист по ИБ | Полнота источников, задержка доставки, аномалии | Добавить до пилота |
| DLP и сканер секретов/ПДн | Экспорт, почта, логи и CI/CD | Специалист по ИБ | Инциденты DLP, секреты в репозиториях, ПДн в логах | Пилот до расширения MVP |

Минимальные критерии автоматического контроля: отсутствуют незашифрованные production-тома и бэкапы; сертификаты не просрочены; ключи ротируются по политике; восстановление копии регулярно проверяется; события доступа к `STRICT` доставляются в SIEM; критическая конфигурационная ошибка блокирует релиз.
