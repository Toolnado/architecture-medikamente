# Задание 2. Проектирование решения

Диаграмма C4 Context целевой архитектуры MVP: [Draw.io](mvp-c4-context.drawio).

## Принятые решения

Я спроектировал MVP вокруг единой системы записи, но разделил данные по назначению и владельцам. Портал пациента и портал ресепшена не обращаются к данным напрямую: все запросы проходят через API Gateway и сервис авторизации.

В целевую архитектуру добавлены следующие системы:

- Identity & Access Management — единая аутентификация, RBAC для сотрудников и ABAC по `patient_id`, филиалу и назначению обработки.
- Consent & Privacy Service — согласия, цели обработки, сроки хранения, запросы на прекращение обработки и удаление.
- Audit & SIEM — неизменяемый журнал доступа и оповещения о подозрительных действиях.
- Data Classification & DLP — автоматическое тегирование, маскирование и контроль выгрузок.
- Data Platform — отдельный аналитический контур с зашифрованной закрытой зоной, очищенной зоной и обезличенными витринами для BI/ML.
- Notification Service — уведомления без медицинских данных в тексте сообщения.

## Privacy by Design

- По умолчанию доступ запрещён; разрешение выдаётся только для конкретной роли, пациента, цели и срока.
- API возвращает минимальный набор полей через отдельные DTO и проверяет объектный доступ на каждой операции.
- Медицинские данные отделены от записей, контактов и платежей; ключи шифрования также разделены по доменам.
- Для аналитики прямые идентификаторы заменяются токенами, а пользователи BI работают только с обезличенными витринами.
- Все изменения согласий и все обращения к данным журналируются.
- Неизвестные или неразмеченные поля не попадают в аналитические витрины, а отправляются в карантин.
